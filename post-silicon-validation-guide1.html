芯片硅后（回片后）测试入门指南

面向第一次参与回片测试的工程师。以典型 SoC（多核 CPU + DDR + 总线互联 + 外设 + 多媒体 + 安全模块）为例，MCU、ASIC、加速器芯片可按需裁剪。正文里带虚线下划线的词都是术语：鼠标悬停看一句话解释，点击跳到第 13 章看详细说明（是什么、为什么需要、测试中怎么用、打个比方）。

0. 写给新手：先看全貌

打个比方：芯片设计像造一辆新车。Pre-silicon 验证相当于在电脑上做仿真、在台架上测发动机；流片（Tape-out）相当于把图纸交给工厂；“回片”就是第一批真车下线。硅后测试就是试车：先看能不能打着火（Bringup），再一个个试车灯、刹车、空调（裸机功能测试），然后让司机真正上路（OS 阶段），最后跑高原、跑高寒、跑长途（性能、功耗、稳定性测试）。

为什么仿真过了还要硅后测试？

仿真、FPGA 原型、Emulator 验证的都是“模型”。真实硅片会额外暴露这些问题：

  • 仿真太慢没跑到的场景：完整的 OS 启动、几天几夜的长时间运行、大量并发。
  • 模拟电路和物理效应：PLL、PHY、SerDes、IO 时序、电源噪声（IR drop）、温度效应。
  • 工艺偏差：每颗芯片的“体质”不同（工艺角 Corner）。
  • 系统级交互：板子上的 PMIC、DDR 颗粒、Flash 等外部器件的兼容性。
  • 规格（Spec）本身的问题：设计完全符合 Spec，但 Spec 和真实使用场景不匹配。

1. 测试台长什么样

在开始讲流程之前，先认识实验室桌面上的东西。一个典型的硅后测试台由主机、调试器、电源、测量仪器和验证板组成，芯片焊在（或插在 socket 里）验证板上。

新手提示：第一次进实验室，先搞清楚每根线接的是什么、每块板子的编号和改动记录（板子可能被人飞线改过）、每颗芯片的编号和 ATE 结果。很多“诡异问题”最后发现是用错了板子或用了坏片。

2.2 板卡准备

验证板（Validation Board）和给客户的参考板（EVB）不同，验证板要尽量“可观测、可调节”：

  • 每路电源独立可调，或用可编程 PMIC；每路有检流电阻和测试点，支持外接电源替代 PMIC。
  • 每路电源有跳线或 0Ω 电阻，可以单独断开，便于找短路和测电流。
  • 时钟源可切换（板载晶振或外部信号源注入），关键时钟引出测试点。
  • 复位和 Boot 模式用拨码开关加测试点，最好还能由继电器自动控制。
  • 引出 JTAG/SWD、UART、Trace 口。
  • DDR 颗粒支持多家供应商；高速接口（PCIe/USB/MIPI/DDR）预留测量点。
  • 通常同时准备 socket 版（方便换片）和直接焊接版（信号质量更好）。

回片前要完成空板上电检查：不装芯片，检查上电时序、电压值、纹波、有无短路。

  • 最小启动镜像：UART 打印、内存读写测试、寄存器 dump 工具。
  • DDR 初始化代码：training 参数和多套备选配置（降频、单 rank、单通道）。
  • 测试框架 + 自动化脚本 + 日志收集。
  • 寄存器头文件：从 IP-XACT / SystemRDL 自动生成，避免手写错误。
  • Bringup 手册：上电步骤、各路预期电流、预期 UART 输出、出问题时的排查决策树。

2.5 ATE 与样片筛选

ATE（如 Advantest V93000、Teradyne UltraFLEX）会对每颗芯片做开短路测试、漏电（IDDQ）、Scan/ATPG、MBIST、边界扫描，并初步测 Vmin/Fmax，给出 corner/bin 信息。

为什么必须先筛片：如果拿一颗有制造缺陷的芯片去 debug，会把“坏片”当成“设计 bug”，白白浪费几天甚至几周。每颗片都要有编号（eFuse chip ID 或丝印）和 ATE 结果，建立样片档案。

3. 阶段二：Bringup 点亮

Bringup 的目标：让芯片“活过来”，能稳定执行代码、访问 DDR、被调试器控制。

3.2 上电

  1. 测量各电源网络对地阻抗，与参考值比较（同批板子互相对比）。
  2. 用可调电源并设置限流（一般为预期电流的 1.5–2 倍），逐路上电，盯着电流表。
  3. 有 PMIC 的板子，先断开 PMIC 输出、用外接电源验证，再切回 PMIC。
  4. 严格按 Spec 的上电时序操作，注意 IO 电源与核心电源的先后关系。
  5. 记录每路电源在复位状态下的电流——这是后续判断异常和静态功耗的基线。

3.3 时钟与复位

  • 时钟：示波器确认晶振起振、幅度和频率；怀疑晶振时用信号源注入外部时钟。通过 CLKOUT 引脚输出各 PLL 分频后的时钟来测量；用 JTAG 读 PLL lock 状态寄存器。PLL 锁不上：查参考时钟、PLL 电源（通常是对噪声敏感的独立模拟电源）、配置参数。
  • 复位：确认上电复位、外部复位引脚、看门狗复位都正常；读复位原因寄存器（后续查死机原因非常有用）。
  • 常见坑：复位释放过早（电源还没稳）、某模块复位极性和 Spec 不一致、复位同步器没有时钟。

3.4 JTAG / 调试链路

  1. 读 IDCODE，确认 JTAG 链的拓扑（多个 TAP 级联时要知道各自的指令寄存器长度）。
  2. 访问 DAP，扫描 CoreSight ROM Table，识别所有核、ETM、CTI 等组件。
  3. 暂停（halt）CPU 核、读写寄存器、读写 SRAM、单步执行。

3.5 BootROM

BootROM 固化在芯片里、无法修改，有 bug 只能 ECO 或换 Boot 模式绕过，所以回片前必须充分仿真。Bringup 时要验证：

  • 各种 Boot 模式：eMMC / SD / SPI NOR / NAND / UFS / USB 下载 / UART 下载 / PCIe。
  • Secure Boot：签名校验、镜像解密、eFuse 读取。务必在未烧写 eFuse 的样片上测试，避免锁死。
  • 错误处理：主镜像失败时能否切到备份镜像。
  • BootROM 要有 UART 打印或状态码，否则卡住时很难定位。卡住时用 JTAG halt 看 PC，对照 ROM 符号表判断卡在哪一步。

3.6 DDR 初始化与 Training

DDR 是 Bringup 中最常见、最耗时的卡点。

打个比方：CPU 和 DDR 颗粒之间有几十根高速信号线，每根线因为走线长度、芯片个体差异，信号到达的时间都略有不同。Training 就像合唱团开唱前调音：逐根线扫描延迟和电压门限，找到每根线“最清楚”的采样点（眼图中心），把参数记下来。
  1. PHY 和控制器上电、配置时钟。
  2. 加载控制器/PHY 寄存器配置（时序参数要与颗粒 datasheet 匹配）。
  3. 执行 training：ZQ 校准 → Write Leveling → Read Gate → 读写眼图训练 → Vref 训练 → CA 训练（LPDDR4/5）。
  4. 跑内存测试验证。

4. 阶段三：Bare Metal 裸机测试

裸机测试指不跑操作系统，测试程序直接读写硬件寄存器来验证各模块。好处是可控、可复现、容易定位，也最接近 pre-silicon 的测试环境。

  1. 下载程序（橙色）：主机上的测试程序（ELF 文件）经 JTAG 调试器进入芯片的 DAP，再由 MEM-AP 通过总线写入片上 SRAM（DDR 初始化后也可以写入 DDR）。调试器随后把 CPU 的 PC 指向程序入口并放行。
  2. 取指执行（蓝色）：CPU 从 SRAM/DDR 取指令执行。开启 Cache 和 MMU 后，指令和数据会先进 Cache。
  3. 配置外设（绿色）：CPU 经总线/互联写外设的寄存器（时钟使能、复位释放、管脚复用、工作模式），也包括给 DMA 设置源地址、目的地址、长度。
  4. DMA 搬运（紫色）：DMA 控制器不经过 CPU，自己通过总线从 DDR 的源区读数据，再写到 DDR 的目的区（也可以是内存到 SRAM、内存到外设）。
  5. 中断通知（灰色虚线）：搬运完成或外设事件发生后，DMA/外设向中断控制器发中断，中断控制器再通知 CPU。
  6. 比对与上报（红色）：CPU 把搬运结果与期望值逐字节比对，把 PASS/FAIL 写入 UART 数据寄存器（走第 3 步同一条路径），经 USB 转串口送到主机；另一种方式是把结果写到 SRAM 中约定的地址，由调试器经 DAP 读回（左侧细红线）。主机脚本解析结果，判定用例通过与否。
新手最常踩的坑：第 4 步 DMA 写内存时，CPU 的 Cache 里可能还存着旧数据。比对前如果不先做 Cache 失效（invalidate），CPU 会读到旧值，误以为 DMA 出了 bug。这就是 Cache 一致性问题。

4.1 启动代码

启动代码负责把芯片带到“可以跑 C 程序”的状态：异常向量表、栈、Cache/MMU 初始化、多核启动（PSCI 或 spin-table）、异常级别切换、中断控制器初始化、时钟/PLL 配置、DDR 初始化、UART 初始化、BSS 清零。

  • 分两层：最小启动（只用 SRAM + UART）和完整启动（DDR + MMU + Cache + 多核 + 中断）。
  • Cache 开、关两种模式都要测，很多 bug 只在其中一种模式下出现。
  • 检查 MMU 页表属性：Device / Normal、Cacheable / Non-cacheable、Shareable。

6.4 ECO / Workaround 流程

  1. 发现并提交 bug，分析定位到硬件 / 软件 / Spec。
  2. 评估影响：功能、性能、功耗、安全、客户可见性、触发概率。
  3. 找 Workaround：软件规避、设 chicken bit、降频、禁用某特性、固件补丁。
  4. 评估 ECO：Metal ECO（只改金属层，成本和周期较低）、全层改版（成本高、周期长）、或不修（写入 Errata + 软件 workaround）。
  5. 评审决策：设计、软件、产品、PM 共同决定。
  6. 实施：修改 RTL/网表 → 仿真和形式等价验证 → 加入回归。
  7. 记录：写入 Errata；workaround 写进驱动/BSP，并按芯片版本号条件启用。
Workaround 要求：用芯片版本号（Revision ID）做条件判断，下一版芯片修好后可自动关闭；量化对性能/功耗的影响；写进 Errata 和软件发布说明。
ECO 决策要考虑：严重程度、有没有可接受的 workaround、ECO 窗口（能否和其他 ECO 合并）、修改引入新 bug 的风险、量产时间。

电压切换PMIC 调压速度、过冲/下冲；“先升压后升频、先降频后降压”的顺序
Governor 行为schedutil / ondemand / performance 下的响应延迟和能效
AVS按芯片 corner 和温度调压，验证每颗芯片的电压表
温控降频触发 throttling 的温度阈值和恢复
devfreqGPU / DDR / NPU 的频率调节

8.4 方法与注意事项

  • 固定环境：锁频（performance governor）、控制环境温度、固定 DDR 频率、关闭后台服务，多次测试取中位数。
  • 与模型对比：同一 workload 在性能模型（gem5、架构模型、Emulator）中跑，对比 IPC、Cache miss、带宽；偏差超过 10% 要分析原因。
  • 性能 bug 常见来源：预取器失效、Cache 替换策略、总线 outstanding 数不足、QoS 配置、DDR 调度策略、TLB miss、频率没生效、编译选项不对。
  • 记录完整：芯片 corner、温度、频率、电压、软件和编译器版本。

13. 术语详解

每个术语按“是什么 / 为什么需要 / 测试中怎么用 / 打个比方”解释。正文中的术语链接会跳到这里。

流程与平台

术语提示用法

正文中带虚线下划线的词都是术语。鼠标悬停显示一句话解释，点击跳转到本章对应条目，按浏览器“后退”返回原位置。

Pre-silicon / Post-silicon硅前验证 / 硅后验证

是什么Pre-silicon 指芯片制造出来之前，用软件仿真、形式验证、FPGA、Emulator 验证设计；Post-silicon（硅后）指拿到真实芯片后的验证。

为什么需要硅前能看到所有内部信号但速度慢；硅后速度快、场景真实，但内部几乎看不见。两者互补。

测试中怎么用硅前用例在硅后复用；硅上发现的问题要回到硅前平台复现、看波形。

打个比方硅前是在风洞里测车模，硅后是真车上路。

Tape-out流片

是什么把最终的版图数据（GDSII/OASIS）交给晶圆厂生产。“回片”指制造好的芯片回到手上，通常要数周到数月。

为什么需要它是设计冻结点，之后再改设计就要 ECO，成本高。

测试中怎么用流片到回片之间的时间就是“回片前准备”窗口，要把板卡、软件、测试计划都准备好。

RTLRegister Transfer Level

是什么用 Verilog/SystemVerilog/VHDL 写的硬件描述代码，相当于芯片的“源代码”。

为什么需要硅上发现的逻辑 bug 最终要追溯到 RTL 的某一行。

测试中怎么用把硅上场景搬到 RTL 仿真中复现，看波形定根因；修复后在 RTL 上验证再做 ECO。

Netlist网表

是什么RTL 经过综合工具转换成的门电路连接关系，是生成版图的依据。

为什么需要网表才是真正被制造的东西；RTL 后期改动未必进了网表。

测试中怎么用最后一轮软件预验证要用与最终网表一致的 RTL 版本，否则软件与硅片可能对不上。

FPGA 原型FPGA Prototype

是什么把芯片设计（或其中一部分）综合到大容量 FPGA 上运行，频率通常几十 MHz。

为什么需要比仿真快上千倍，能跑 OS 和驱动，让软件在回片前就开始开发。

测试中怎么用预先调通驱动、测试框架；注意 FPGA 上的 PLL、DDR PHY、模拟 IP 往往是替代品，硅上要单独处理。

打个比方真车造出来之前先拼一辆“样车”，外形不同但开起来逻辑一样。

Emulator硬件仿真加速器

是什么Cadence Palladium、Synopsys Zebu、Siemens Veloce 等专用设备，能把整颗芯片设计跑到 MHz 级别，同时可以抓内部波形。

为什么需要介于软件仿真（慢但全可见）和 FPGA（快但难调试）之间，适合跑 BootROM、启动流程和复现硅上 bug。

测试中怎么用回片前跑通启动链；回片后用相同激励复现硅上问题，看波形找根因。

Bringup点亮 / 启动调试

是什么回片后让芯片第一次工作起来的过程：上电、时钟、复位、JTAG 连通、BootROM、DDR。

为什么需要后续所有测试都依赖它；它也是最容易暴露致命问题的阶段。

测试中怎么用按 Bringup 手册逐步推进，每一步都有明确的成功标志（见第 3 章）。

打个比方新车第一次打火、挂档、起步。

Bare Metal裸机

是什么没有 Linux 等操作系统，测试程序直接在 CPU 上运行并读写硬件寄存器。

为什么需要环境简单、可控、可复现，出问题时容易判断是硬件还是软件。

测试中怎么用Bringup 之后用裸机用例逐个验证各模块；OS 下的疑难问题也常回到裸机写最小复现用例。

Firmware固件

是什么运行在操作系统之下、最贴近硬件的软件，负责启动、初始化和安全服务。

为什么需要操作系统启动前必须有人把时钟、DDR、安全环境准备好。

测试中怎么用固件出问题通常表现为“起不来”，用 JTAG 和 UART 早期打印定位。

BSPBoard Support Package，板级支持包

是什么启动代码、设备树、驱动、配置文件等的集合，让某个 OS 能在特定芯片和板子上运行。

为什么需要它是交付给客户和量产的软件基础。

测试中怎么用硅后测试中发现的 workaround 最终要沉淀到 BSP 中。

HALHardware Abstraction Layer，硬件抽象层

是什么一组统一的函数接口（如“打印”“延时”“读寄存器”“上报结果”），底下针对不同平台有不同实现。

为什么需要让同一份测试用例在仿真、Emulator、FPGA、硅片上都能跑；在 Android 中，HAL 让上层框架不用关心具体硬件型号。

测试中怎么用测试框架通过 HAL 实现 pre-silicon 用例复用；OS 阶段 Android HAL 是 Camera/Audio 等功能测试的入口。

打个比方万能充电器的转换头：电器（用例）不变，换个转换头（HAL 实现）就能插到不同国家的插座（平台）上。

EVB / 验证板Evaluation Board / Validation Board

是什么EVB 是给客户评估用的参考板；验证板是内部硅后测试用的板，测试点和可调能力更多。

为什么需要芯片必须焊在板子上，有电源、时钟、存储、接口才能工作。

测试中怎么用每块板都要编号、记录版本和改动；问题复现时要换板对比。

Spec规格书

是什么芯片和各 IP 的设计规格，包括功能描述、寄存器手册、编程指南、电气特性。

为什么需要它是判断“对还是错”的唯一依据。

测试中怎么用Bug 报告要引用 Spec 章节；有时问题出在 Spec 本身。

制造、筛选与工艺

ATEAutomatic Test Equipment，自动测试设备

是什么Advantest V93000、Teradyne UltraFLEX 等机台，通过探针或插座给芯片施加测试向量并检测输出。

为什么需要能快速筛出制造缺陷，并给出每颗芯片的漏电、Vmin、Fmax 等数据。

测试中怎么用样片先过 ATE 再上板；遇到“只有个别片失败”时，查该片的 ATE 数据。

打个比方新车下线时的出厂检测线：每辆车都过一遍刹车、灯光、尾气检测。

Corner（SS / TT / FF）工艺角

是什么制造中晶体管特性会有偏差。SS（慢-慢）速度慢、漏电小；TT 是典型；FF（快-快）速度快但漏电大。工厂可专门做 corner lot（拆分批次）产出不同角的样片。

为什么需要量产芯片会分布在各个角，规格必须对所有角都成立。

测试中怎么用性能/Vmin 看 SS 片（最慢），漏电/功耗看 FF 片（最耗电），都要覆盖。

打个比方同一批运动员，有人天生跑得快但饭量大（FF），有人跑得慢但省粮（SS）。

Bin / 分 bin分档

是什么根据 ATE 测试结果，把芯片按能跑的频率、功耗等分为不同档次，甚至做成不同型号出售。

为什么需要提高良率和收益；也给 AVS 提供每颗芯片的电压参考。

测试中怎么用记录每颗样片的 bin，测性能、功耗时说明用的是哪一档。

Scan / ATPG扫描测试 / 自动测试向量生成

是什么设计时把触发器连成扫描链，ATPG 工具自动生成测试向量，在 ATE 上检测固定故障、时延故障等制造缺陷。

为什么需要功能测试无法覆盖所有晶体管，扫描测试覆盖率可达 95% 以上。

测试中怎么用主要在 ATE 上执行；scan pattern 也常用于 Vmin shmoo。

MBISTMemory Built-In Self-Test

是什么芯片内集成的测试控制器，对片上 SRAM/ROM 自动执行 March 等算法并报告结果。

为什么需要片上存储器面积大、缺陷多，必须逐 bit 检查；部分设计还支持冗余修复。

测试中怎么用ATE 上执行；硅后可通过 JTAG 触发，排查 SRAM 相关问题。

IDDQ静态电源电流

是什么芯片在没有翻转的静止状态下测得的电源电流。

为什么需要短路、桥接等缺陷会让 IDDQ 明显偏大；它也反映漏电水平（corner）。

测试中怎么用上电时电流偏大，先对比该片的 ATE IDDQ 数据，判断是芯片本身还是板子问题。

FAFailure Analysis，失效分析

是什么对失效芯片做 X-ray、开封、热点定位、切片、电子显微镜观察等。

为什么需要有些问题（工艺缺陷、封装问题）只能靠物理分析确认。

测试中怎么用预留部分样片给 FA；疑似制造缺陷时送 FA。

FIBFocused Ion Beam，聚焦离子束

是什么用离子束在芯片金属层上做微米级的切割和沉积，相当于在芯片上“飞线”。

为什么需要可以在不重新流片的情况下验证 ECO 修改是否有效，或引出内部信号。

测试中怎么用重要 ECO 前先在样片上做 FIB 验证；也用于物理定位问题。

Latch-up闩锁效应

是什么CMOS 中的寄生晶闸管被触发（如上电时序错误、IO 电压超限），电源到地形成低阻通路，电流剧增。

为什么需要会永久损坏芯片，必须通过设计和测试（JESD78）保证不易触发。

测试中怎么用上电发烫、电流猛增时立即断电；严格遵守上电时序，首次上电限流。

IR drop电压降

是什么根据 V=I×R，大电流流过芯片和板子的电源网络时，到达晶体管的实际电压比电源输出低。

为什么需要电压降低会让电路变慢，在高负载时导致时序失败。

测试中怎么用只在高负载时出现的随机错误要怀疑 IR drop；用示波器在芯片近端测电压跌落。

Signal Integrity信号完整性

是什么高速信号经过 PCB 走线、连接器后，会出现反射、串扰、衰减、振铃等失真。

为什么需要信号失真会导致接收端采样错误，DDR、PCIe 等高速接口尤其敏感。

测试中怎么用示波器看波形和眼图；调整驱动强度、ODT 等参数改善。

Reliability可靠性

是什么评估芯片在寿命期内的失效率，涵盖老化、静电、闩锁、封装、软错误等。

为什么需要产品要保证数年甚至十几年（车规）的使用寿命。

测试中怎么用见第 10.4 节各项试验。

HTOLHigh Temperature Operating Life

是什么在高温（如 125°C）、高于额定电压下让芯片持续工作约 1000 小时，再测试是否失效。

为什么需要用加速应力在短时间内模拟多年的使用，估算失效率。

测试中怎么用由可靠性团队执行；HTOL 后复测 Vmin/Fmax 评估老化影响。

电源、时钟与复位

PMICPower Management IC，电源管理芯片

是什么板上的专用芯片，内含多路 DC-DC 和 LDO，按时序输出 SoC 需要的各路电压，通常可通过 I2C/SPI 编程调压。

为什么需要SoC 需要多种电压（核心、IO、DDR、模拟），而且要按顺序上电、能动态调压（DVFS）。

测试中怎么用Bringup 初期常绕过 PMIC 用外部电源排除问题；DVFS 测试要验证 PMIC 调压速度和过冲。

打个比方家里的配电箱，把总闸分成厨房、卧室、空调各路，每路电压电流不同。

DC-DC / LDO开关稳压器 / 低压差线性稳压器

是什么DC-DC 效率高但有开关纹波；LDO 效率较低但输出干净。

为什么需要大电流的 CPU 核心用 DC-DC，对噪声敏感的 PLL、模拟电路用 LDO。

测试中怎么用用示波器测纹波；PLL 抖动大时检查其 LDO 供电。

Shunt Resistor检流电阻 / 分流电阻

是什么毫欧到欧姆级的精密电阻，串联在每路电源上，电流 = 两端电压 ÷ 电阻值。

为什么需要功耗测量和异常电流定位都依赖它。

测试中怎么用接电源分析仪或采集卡；阻值太大会造成压降，太小则分辨率不够。

Power Sequence上电时序

是什么Spec 规定的各路电源上电先后顺序、间隔，以及与复位释放的关系。

为什么需要顺序错误可能导致 IO 倒灌电流、闩锁、内部状态异常。

测试中怎么用用示波器多通道同时抓各路电源和复位，核对时序（见图 2）。

Crystal / OSC晶振

是什么利用石英谐振产生稳定频率的元件，为 PLL 提供参考时钟。

为什么需要没有时钟芯片就不会动。

测试中怎么用Bringup 先确认晶振起振；怀疑晶振时用信号源注入外部时钟。

打个比方乐队的节拍器。

PLLPhase-Locked Loop，锁相环

是什么模拟电路，把 24MHz 等参考时钟倍频到 GHz 级别，并保持相位锁定。

为什么需要芯片内各模块需要不同的高频时钟，都由 PLL 产生。

测试中怎么用检查 lock 状态寄存器、通过 CLKOUT 测频率；PLL 锁不住时查参考时钟、电源噪声和配置参数。

打个比方变速自行车的齿轮组，把慢慢踩的脚踏变成飞快的车轮转速。

CLKOUT时钟输出

是什么芯片上可配置的调试引脚，能输出内部选定时钟（通常经过分频）。

为什么需要内部时钟无法直接测量，CLKOUT 是验证 PLL 和时钟树配置的窗口。

测试中怎么用Bringup 时依次输出各 PLL 时钟，用示波器或频率计确认。

SSCSpread Spectrum Clocking，展频

是什么时钟频率在中心值附近按小幅度（如 0.5%）缓慢调制。

为什么需要把能量分散到更宽的频带，降低 EMI 峰值，帮助通过电磁兼容认证。

测试中怎么用验证开启展频后 PCIe/USB 等接口仍能稳定工作。

POR / 复位Power-On Reset

是什么复位把芯片内部所有状态置为初始值。POR 是上电时自动产生的复位，此外还有外部复位引脚、看门狗复位、软件复位等。

为什么需要电源和时钟稳定之前芯片状态不确定，必须复位后才能可靠启动。

测试中怎么用示波器看复位信号释放时机；读复位原因寄存器判断上次是因为什么复位。

Watchdog看门狗

是什么一个倒计时定时器，软件必须定期重置它；软件卡死没重置时，计时到零就复位系统。

为什么需要防止系统永久死机。

测试中怎么用验证超时复位功能；自动化测试中用看门狗让挂死的用例自动恢复。

打个比方值班员要每隔一段时间按一次按钮，不按就自动报警。

PMU（电源管理单元）Power Management Unit

是什么芯片内控制各电源域上下电、时钟开关、低功耗模式进出和唤醒的硬件状态机，有时配有小 MCU。注意 PMU 也可能指性能监控单元，见下一条。

为什么需要低功耗管理需要严格的顺序（隔离、保存、断电、唤醒、恢复）。

测试中怎么用休眠唤醒失败时读 PMU 状态寄存器，看状态机卡在哪一步。

PMU（性能监控单元）Performance Monitoring Unit

是什么CPU 内部的一组计数器，可统计周期数、指令数、Cache/TLB miss、分支预测失败等事件。

为什么需要性能分析的基础数据来源，能看出瓶颈在哪里。

测试中怎么用用 perf、Streamline 采集；与性能模型的统计值对比找性能 bug。

调试与启动

JTAGJoint Test Action Group（IEEE 1149.1）

是什么最常用的芯片调试接口，信号线有 TCK（时钟）、TMS（模式）、TDI（数据入）、TDO（数据出）、可选 TRST（复位）。最初用于板级边界扫描测试，现在主要用于调试。

为什么需要芯片刚回来时没有任何软件，JTAG 是唯一能“看进去”的通道：暂停 CPU、读写寄存器和内存、下载程序。

测试中怎么用Bringup 第一个里程碑就是 JTAG 读到 IDCODE；之后用于下载裸机程序、调试挂死、读状态寄存器。

打个比方医生的内窥镜：不用开刀，从一个小口进去看内部情况。

SWDSerial Wire Debug

是什么ARM 定义的两线（SWDIO + SWCLK）调试协议，常见于 MCU。

为什么需要节省引脚，功能与 JTAG 调试相当。

测试中怎么用用法与 JTAG 相同，连接调试器即可。

TAP / IDCODETest Access Port / 器件识别码

是什么TAP 是每个 JTAG 设备内部的控制器；IDCODE 是 32 位编号，包含厂商、器件、版本。

为什么需要能读出 IDCODE 说明 JTAG 物理链路通了，是调试的第一步。

测试中怎么用读不到 IDCODE 时，查电平、TCK 频率、TRST、调试电源域、安全锁定。

DAPDebug Access Port

是什么ARM CoreSight 的调试入口，由 DP（Debug Port，连外部调试器）和多个 AP（Access Port，通向不同目标）组成。

为什么需要把一个外部调试接口分发到多个 CPU 核、多条总线。

测试中怎么用能连 DAP 后扫描 ROM Table，识别所有调试组件。

MEM-AP / AXI-AP内存访问端口

是什么DAP 中的一种 AP，可以直接在系统总线（AXI/AHB/APB）上发起读写。

为什么需要CPU 跑飞、挂死或还没启动时，调试器仍能读写内存和外设寄存器。

测试中怎么用下载程序到 SRAM、CPU 挂死后读错误寄存器——是 Bringup 的救命通道。

CoreSightARM 调试跟踪架构

是什么ARM 定义的一整套片上调试/跟踪组件和互连标准：DAP、ROM Table（组件目录）、ETM（指令跟踪）、CTI（交叉触发）、Funnel/ETB/TPIU（trace 汇聚与输出）等。

为什么需要多核 SoC 需要统一、可发现的调试基础设施，调试器才能自动识别和控制。

测试中怎么用Bringup 时扫描 ROM Table 确认所有组件可见；调试脚本里要描述 CoreSight 拓扑。

打个比方大楼的监控系统：摄像头（ETM）、对讲机（CTI）、监控室总入口（DAP）、楼层索引表（ROM Table）。

Trace（ETM / ETB / TPIU）指令跟踪

是什么ETM 实时压缩记录 CPU 执行路径；ETB/ETF/ETR 是片上存 trace 的缓冲区；TPIU 把 trace 输出到外部引脚给 trace 设备采集。

为什么需要断点会改变时序，有些问题一打断点就消失；trace 不打断执行，能看到挂死前最后发生了什么。

测试中怎么用随机挂死后读片上 trace buffer 回溯；用外部 trace 做长时间性能分析。

打个比方飞机的黑匣子。

CTICross Trigger Interface

是什么CoreSight 组件，把一个核的调试事件（如断点命中）广播给其他核或 trace 组件。

为什么需要多核问题需要在同一时刻冻结所有核的状态。

测试中怎么用配置“任一核命中断点则全部暂停”，调试多核一致性问题。

UART通用异步收发器

是什么两根线（TX/RX）的异步串口，经 USB 转串口连到电脑。

为什么需要初始化简单，往往是第一个能工作的外设，用来输出日志和交互命令。

测试中怎么用BootROM 状态、测试结果、内核日志都从 UART 输出；自动化脚本解析 UART 日志。

BootROM片上启动只读存储器

是什么制造时写死在芯片里的代码。上电复位后 CPU 从这里开始执行，负责最基本的初始化、读取 Boot 模式、从外部存储加载下一级程序，并可执行 Secure Boot 校验。

为什么需要芯片刚上电时外部存储里的程序还没法直接执行，需要一段内置代码“引导”。

测试中怎么用验证各 Boot 模式和 Secure Boot；卡住时 JTAG 看 PC 并对照 ROM 符号表。因为改不了，有 bug 只能 ECO 或绕过。

打个比方汽车的点火开关电路：出厂固定，钥匙一拧，它去唤醒发动机电脑。

Boot Mode启动模式

是什么BootROM 根据拨码引脚或 eFuse 选择从 eMMC、SD、SPI NOR、NAND、UFS、USB、UART、PCIe 中的哪个加载程序。

为什么需要不同产品用不同存储；USB/UART 下载模式还是板子“变砖”后的救援通道。

测试中怎么用逐个验证每种 Boot 模式；自动化测试中用继电器切换。

SPL / BL2Secondary Program Loader

是什么能放进片上 SRAM 的小型启动程序（U-Boot 中叫 SPL，ARM 可信固件中叫 BL2），负责时钟配置、DDR 初始化与 training，然后加载 ATF、U-Boot 等。

为什么需要DDR 初始化前只有容量很小的 SRAM 可用，大程序放不下。

测试中怎么用DDR 调试主要在这一层进行。

ATF / TF-A / BL31Trusted Firmware-A

是什么ARM 官方开源固件，运行在 EL3（最高特权级），常驻内存，提供 CPU 上下电（PSCI）、安全/非安全世界切换、安全配置。

为什么需要Linux 不能直接控制核的上下电和安全配置，需要通过 ATF。

打个比方离开房间时随手关灯（但电闸还开着）。

Power Gating电源门控

是什么用开关晶体管断开某电源域的供电，比时钟门控更省电但进出更慢，且内部状态会丢失。

为什么需要漏电在先进工艺中占比很大，只有断电才能消除。

测试中怎么用验证断电后漏电下降到预期，上电后功能正常。

Retention状态保持

是什么模块主电源断开时，用单独供电的 retention 寄存器或低电压 SRAM 保存状态。

为什么需要避免每次唤醒都要完整重新初始化，缩短唤醒时间。

测试中怎么用休眠前写入特定值，唤醒后检查是否保持；唤醒后挂死常与 retention 丢失有关。

Isolation隔离

是什么断电域的输出会变成不确定电平，隔离单元把它们固定为 0 或 1。

为什么需要避免不确定信号导致其他模块出错或漏电。

测试中怎么用某域断电后其他模块出现异常，要检查隔离使能顺序。

Leakage漏电 / 静态功耗

是什么晶体管即使不翻转也存在漏电流，先进工艺下占总功耗相当比例。

为什么需要决定待机功耗；高温下漏电增大，还可能形成“发热—漏电—更热”的正反馈。

测试中怎么用在多个温度、多个 corner 下测静态电流；FF 片和高温是最坏情况。

Dynamic Power动态功耗

是什么α 是翻转率、C 是负载电容、V 是电压、f 是频率。电压影响是平方关系。

为什么需要理解它就理解了 DVFS 为什么有效：降一点电压就能省很多电。

测试中怎么用测不同 OPP、不同负载下的功耗曲线，与功耗模型对比。

WFI / WFEWait For Interrupt / Event

是什么ARM 指令，让 CPU 停在低功耗状态直到中断或事件到来。

为什么需要最基础、最快的 CPU 空闲省电方式，也是更深 idle 状态的入口。

测试中怎么用测 WFI 状态功耗和唤醒延迟。

Suspend-to-RAMSTR / 待机休眠

是什么系统状态保存在 DDR 中，DDR 进入自刷新，CPU 和大部分外设断电，唤醒后从内存恢复。

为什么需要手机息屏、笔记本合盖的待机模式。

测试中怎么用测待机电流、唤醒时间、唤醒源；数千次休眠唤醒循环。

Benchmark基准测试

是什么公认的标准测试程序，结果可以横向比较，例如 SPEC CPU、CoreMark、STREAM、GFXBench。

为什么需要量化性能，与目标和竞品比较。

测试中怎么用固定环境多次运行，与性能模型对比。

IPCInstructions Per Cycle

是什么执行的指令数除以时钟周期数。性能 ≈ IPC × 频率。

为什么需要排除频率因素，直接反映微架构设计是否达标。

测试中怎么用用 PMU 计数器测量，与性能模型对比，偏差大说明可能有性能 bug。

Bandwidth / Latency带宽 / 延迟

是什么带宽单位如 GB/s，延迟单位如 ns 或周期数。

为什么需要内存带宽和延迟往往是系统性能瓶颈。

测试中怎么用STREAM 测带宽，pointer chasing 测延迟；画出延迟随负载变化的曲线。

打个比方带宽是公路有几条车道，延迟是从 A 开到 B 要多久。

稳定性与裕量

Shmoo参数扫描图

是什么横轴、纵轴各是一个参数（常见电压×频率、电压×温度），每格标记 Pass/Fail，形成工作区域图（见图 6）。名字来源于早期图形酷似漫画中的生物 Shmoo。

为什么需要直观展示芯片的工作窗口和裕量，确定 Vmin/Fmax 和 OPP。

测试中怎么用用对时序最敏感的负载，在多温度、多芯片上自动化扫描。

打个比方给运动员画“能力地图”：多快的速度能坚持多久。

Vmin / Fmax最低工作电压 / 最高工作频率

是什么两个关键电气指标，决定芯片的功耗和性能上限。

为什么需要OPP 电压要在 Vmin 基础上留裕量；产品频率不能超过 Fmax。

测试中怎么用shmoo 扫描；覆盖多温度、多 corner、老化后复测。

Temperature Inversion温度反转效应

是什么传统认识是高温更慢，但在先进工艺、低电压下，低温时阈值电压升高的影响更大，电路反而变慢。

为什么需要只测高温会漏掉低温失败的问题。

测试中怎么用Vmin shmoo 必须覆盖低温点（如 -40°C）。

Power Virus功耗病毒

是什么精心构造的指令序列，让尽可能多的电路同时翻转，产生最大功耗或最剧烈的电流变化（di/dt）。

为什么需要真实应用很难达到最坏情况，需要它来验证电源、散热和时序裕量。

测试中怎么用作为 shmoo 和电源完整性测试的负载。

问题处理与协作

ECOEngineering Change Order，工程变更

是什么对已流片设计的修改。Metal ECO 只改金属层；全层改版（respin）要重做所有掩膜，成本和周期更高。

为什么需要修复硅上发现的硬件 bug。

测试中怎么用硬件 bug 确认后进入 ECO 评估；ECO 修改要经过仿真、形式等价验证，必要时先做 FIB 验证。

打个比方新车发现问题后的“召回改款”：小改只换零件，大改要重开模具。

Metal ECO金属层工程变更

是什么设计时在芯片里撒下备用逻辑单元（spare cell），ECO 时只改金属连线把它们接入电路。

为什么需要只需重做少量金属层掩膜，甚至可以利用已加工到一半的晶圆，节省时间和成本。

测试中怎么用评估 bug 能否用 Metal ECO 修复是 ECO 决策的关键一步。

Chicken Bit功能禁用位

是什么寄存器中预留的开关，用于关闭预取、某个优化、新特性等。名字来自“胆小鬼”——没把握的新功能都留条退路。

为什么需要新功能有 bug 时可以通过配置关闭，避免改版。

测试中怎么用定位问题时逐个关闭 chicken bit 缩小范围；确认后作为 workaround 写入启动代码。

Workaround规避方案

是什么通过修改驱动流程、设置 chicken bit、降频、禁用功能、固件补丁等方式避开 bug 的触发条件。

为什么需要ECO 周期长、成本高，很多 bug 可以通过 workaround 满足量产要求。

测试中怎么用按芯片版本号条件启用；量化对性能/功耗的影响；写入 Errata。

Errata芯片勘误表

是什么对客户和内部发布的已知问题列表，每条包含编号、描述、触发条件、影响、workaround、修复计划。

为什么需要让软件开发者和客户知道哪些地方要绕开。

测试中怎么用硅后测试的重要产出之一；驱动中的 workaround 代码要注明 Errata 编号。

Revision ID芯片版本号

是什么寄存器或 eFuse 中的版本编码，每次 ECO 改版递增（如 A0 → A1 → B0）。

为什么需要同一份软件要支持多个芯片版本，需要知道当前是哪一版。

测试中怎么用workaround 代码根据版本号决定是否启用。

Triage问题分诊

是什么团队定期开会过一遍新提交和未解决的 bug，分级、分类（硬件/软件/板级/Spec）、指派负责人。

为什么需要回片初期 bug 很多，必须集中精力在阻塞性问题上。

测试中怎么用Bringup 期间每周 2–3 次，Blocker 级问题每天跟进。

Regression回归测试

是什么定期或在每次软件更新后，自动执行整套用例并对比结果。

为什么需要修一个 bug 可能引入另一个；workaround 也可能影响其他功能。

测试中怎么用每晚自动回归，结果进看板；失败用例要分析是新问题还是环境问题。

CIContinuous Integration，持续集成

是什么用 Jenkins、GitLab CI 等系统串起编译、烧写、上电、测试、收集日志的全流程。

为什么需要测试板和用例数量多，靠人工跑不过来，也容易出错。

测试中怎么用配合可编程电源、继电器、串口服务器实现无人值守测试。

测量仪器

Oscilloscope示波器

是什么以高采样率采集模拟电压并显示波形，可以测频率、幅度、上升时间、抖动、眼图。

为什么需要上电时序、电源纹波、时钟质量、高速信号质量都需要看真实波形。

测试中怎么用带宽要足够（信号最高频率的 3–5 倍）；地线尽量短；多通道同时抓电源和复位。

Logic Analyzer逻辑分析仪

是什么只关心高低电平，但通道数多（16–几百路），能长时间记录并解码协议。

为什么需要看清多根信号之间的时序关系和协议内容。

测试中怎么用调试 I2C 无应答、SPI 数据错位、GPIO 时序；采样率至少为信号频率的 4–10 倍。

Power Analyzer / SMU电源分析仪 / 源测量单元

是什么如 Keysight N6705C、Keithley SMU，可输出精确电压并以高采样率记录电流，从微安到数安。

为什么需要功耗测试需要高精度、多通道、可记录的电流数据。

测试中怎么用直接给芯片某路电源供电并测量；注意量程切换和线损补偿。

Protocol Analyzer协议分析仪

是什么串接在链路中，记录每个数据包和链路状态变化。

为什么需要高速接口问题（链路训练失败、兼容性）只看波形难以定位。

测试中怎么用PCIe 链路训练、USB 枚举失败时抓包分析。

Thermostream / 温箱温度控制设备

是什么温箱把整块板放进可控温腔体；Thermostream 用罩子扣在芯片上吹温控气流，变温快。

为什么需要芯片规格要在整个温度范围成立，高低温测试必不可少。

测试中怎么用温度 shmoo、高低温功耗、高温长稳；注意低温时防止结露。
